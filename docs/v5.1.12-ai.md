# v5.1.12 AI 服务商与模型

AI 仍完全可选。新配置以服务商共享协议、地址、密钥环境变量引用、启用状态和连接超时；每个服务商可以添加多个模型。模型分别配置显示名、Model ID、文本、图片理解、推理兼容参数、输出上限和每日请求上限。新增对象默认停用，不会因为加载预设、添加模型或指定默认任务而发起生成。

## 配置与旧数据

配置继续存储于现有 `SiteConfig(key="ai-writing")` JSON，不引入 AI 数据库迁移。原 `providers[]` 在代码/API 中继续表示模型调用配置，保留 UUID、模型名、地址、`key_env`、启用状态和 `default_provider`；调用历史的 `provider_id` 继续指向同一模型 UUID。新增 `services[]` 和模型可选 `service_id`，以及 `task_defaults`。旧配置无需重填；新模型的连接属性在调用时从所属服务商解析，旧独立模型继续使用自身原配置。不会自动分组、改地址、改默认服务商、扩大网络授权或复制密钥明文。

管理页的“历史独立模型配置”保留旧配置编辑入口；“服务商与模型”用于共享连接的新配置。修改服务商连接将影响其下所有模型，仍需保存修订并在每次调用前确认发送范围。密钥仍仅由服务端 `LJ_AI_KEY_*` 环境变量提供，前端、配置 JSON、普通数据库备份只保存变量名。不要把密钥写进 URL、模型 ID 或名称。

实际已有任务为完整文章生成、润色、扩写、续写、标题、摘要、标签、动态字段、旅行行程、美食点评；没有新增业务任务。图片理解属于这些任务的可选输入，须单独勾选所选照片授权；只发送去元数据的压缩预览。每项任务可指定自己的默认模型，也可继承原默认模型或明确不预选。缺失、删除、停用、无文本能力的默认模型会显示受影响任务；不会选用其他启用模型，更不会自动转向另一付费服务商。删除模型保留默认引用，直到管理员主动修复。

## 协议与能力

| 协议 | 生成与图片 | 模型列表 | 用量 |
| --- | --- | --- | --- |
| OpenAI Compatible | Chat Completions；JPEG data URL | `GET /models` | prompt/completion tokens |
| Ollama 原生 | `/api/chat`；base64 images | `GET /api/tags` | prompt_eval_count/eval_count |
| Anthropic Messages | `/messages`；base64 image source，独立 system | `GET /models` | input/output tokens |
| Gemini 原生 | `models/{id}:generateContent`；inlineData，systemInstruction | `GET /models`，仅列出 generateContent 模型 | prompt/candidates tokens，另计返回的 thoughtsTokenCount |

所有协议都走同一现有调用登记、幂等请求、取消/未知状态、用量记录和内容交换预览校验层。结果不会自动发布或修改文章。没有自动网络重试。返回的用量不是费用计算，未知用量不表示免费。

当前业务没有流式响应接口，所有协议均非流式；不宣称支持流式、工具调用、嵌入、音频、视频或扩展思考预算。模型列表不推断视觉/推理能力，须根据所用模型官方说明确认后配置；列表仅取单次响应，可能不完整，不支持列表或无权限时仍可手动添加。列表与生成使用同一受控网络传输。

推理开关表示模型的参数兼容模式，不代表会强行启用服务商的扩展思考。推理模式省略可选 JSON 格式参数和 temperature；OpenAI 默认改用 `max_completion_tokens`，可针对兼容服务选择 `max_tokens`、`max_completion_tokens` 或不发送，指令角色也可选择 system/developer。其他协议按其自身 token 参数序列化。禁用原生 JSON 模式时仍要求模型返回严格 JSON，并且必须通过同一业务校验；不支持的字段不会因为能力勾选而放行。

连接测试复用上述调用层，发送所选类型必要的格式规范和合成测试文字，不读取真实文章或照片；可能计费，须明确确认，重复测试复用同一请求身份。测试成功仅代表该次响应和格式校验成功。页面保留各模型最近调用状态以及完整最近调用记录，不能将此状态理解为所有服务商的兼容认证。

## 网络安全

公网仅允许 HTTPS，拒绝用户信息、查询参数、片段、编码路径和控制字符；DNS 所有地址都必须通过校验，连接固定已验证 IP 并保留 Host/TLS SNI，不重新解析原域名。拒绝重定向、私网/元数据/混合 DNS、超时和超大响应；错误不回显远端正文。请求上限 1 MiB、响应上限 2 MiB，连接/读取超时遵从原限制。认证分别采用 Bearer、`x-api-key`（Anthropic，附版本头）或 `x-goog-api-key`（Gemini），不把密钥放进查询参数。

本地例外仍仅适用于原有 Ollama 协议，并要求服务端 `LJ_AI_OLLAMA_ALLOWED_ORIGINS` 精确授权 Origin；主机名另须 `LJ_AI_OLLAMA_ORIGIN_IPS` 绑定该 Origin 的固定 IP。不能借一个服务的授权访问另一服务，也不能通过改协议放宽授权。LM Studio 预设使用官方示例 `http://localhost:1234/v1`，但现有安全策略拒绝该本地 OpenAI 地址；使用它需要自行部署受控公开 HTTPS 网关并配置密钥引用，不能通过预设绕过安全策略。没有新增默认内网访问权限。

## 验证与回滚边界

新增测试使用合成数据和模拟协议响应，覆盖四种协议的真实请求结构、文本/图片序列化、模型列表、认证头、用量、无效凭据/模型、429/500、超时、非法与超大响应、SSRF、DNS 重绑定、IP 固定、重定向拒绝、停用服务、缺失默认模型、旧 JSON 和调用 UUID 兼容，并通过现有预览/幂等调用管线验证。没有使用真实服务商密钥，没有发起真实付费调用。真实服务商端到端验证待进行；不得将模拟通过写成全部真实服务商已实测。

AI 本身无需 Alembic 迁移，不必修改现有 Compose 或重填旧配置。升级前仍应按整版升级文档备份数据库及媒体。旧程序无法读取新增配置字段；回退到旧程序时应恢复对应旧版本备份，不能只替换镜像而保留已保存的新 AI 配置。整版的其他数据库迁移及恢复要求以升级文档为准。
